### Changelog


#### Unreleased: 0.2.0b1

- **Breaking Changes:**
  - Date-only writes now require complete ISO dates or Python `date` objects.
  - Datetime writes now require complete ISO timestamps with an explicit offset
    or timezone-aware Python `datetime` objects. The client no longer guesses
    two-digit years, normalizes slash-separated dates, assumes midnight or UTC,
    strips time values, or uses the executing machine's timezone implicitly.
  - Select, linked-row, file, collaborator, and lookup reads now return
    identity-bearing records instead of labels or raw dictionaries.
  - Replaced `TableLinkField.get_options()` with `get_linked_rows()`, which
    preserves row IDs.
  - Select field `options` now returns `SelectOption` records; the redundant
    raw-dictionary `options_details` property was removed.
  - Removed file upload and download behavior from `FileRowValue`. Uploads are
    now client operations and row assignment is explicit.
  - Removed the detached `FilterValidator` and unused `Filter.query_string`
    encoding. Row queries continue to use Baserow's JSON filter tree.
  - Split singular and plural row writes into fixed contracts: `add_row()` and
    `update_row()` return one Row, while `add_rows()` and `update_rows()` accept
    non-empty lists and return lists. `add_rows(mapping)` is no longer accepted.
  - Removed `FieldList`, `RowValueList`, all per-type RowValue classes, their
    package exports, and RowValue-specific exceptions. Field classes are now the
    sole value-semantic dispatch.
  - `Table.fields` and `Table.writable_fields` now return ordered, read-only
    mappings. Iterating them yields field names; use `.values()` for Fields.
  - `Row.values` now returns an ordered, read-only mapping of decoded values;
    use `Row.raw_values` for the original Baserow response values.
  - Removed staged Row item assignment, no-argument `Row.update()`, and the
    `memory_only` update mode. `Row.update(values)` requires an explicit mapping.
  - `Table.update_rows()` no longer accepts Row objects; each list item must be
    a mapping containing an explicit row ID.
  - Root-package exports are now explicit and limited to the supported client,
    table, row, Field, filter, and Baserow value-record concepts.
- **Field Semantics:**
  - Added field-owned `decode_value`, `validate_value`, and `encode_value`
    operations. `format_for_api` remains as a compatibility alias.
  - Preserved Baserow decimal strings and ISO date strings on ordinary reads.
  - Added explicit date parsing and metadata-driven display helpers.
  - Number validation now checks precision and negativity with internal
    `Decimal` arithmetic without exposing `Decimal` as a row value.
  - Unknown hosted field types retain their API type, metadata, and raw values
    without emitting routine warnings.
  - Added independent `SelectOption`, `LinkedRow`, `BaserowFile`, `Collaborator`,
    and `LookupEntry` records with retained raw metadata.
  - Added strict select-option and linked-row label resolvers that reject
    missing or duplicate matches without narrowing ordinary Baserow writes.
  - Select, link-row, and file encoders accept the documented ID, label,
    returned-object, comma-separated, and empty forms supported by each field.
  - Added dedicated read-only `UUIDField` and `AutonumberField` support while
    preserving hosted string and integer read representations.
  - Count fields now reuse number-result semantics. Formula button objects and
    unknown computed result shapes remain raw and lossless.
- **Filters:**
  - Added advisory `FilterCompatibility` results for supported, unsupported,
    and unknown field/operator combinations.
  - Updated configured field compatibility lists from the generated Baserow API
    documentation. Unknown operators still pass through to hosted Baserow.
- **Files:**
  - Added `Baserow.upload_file()` and `Baserow.upload_file_via_url()`, returning
    unattached `BaserowFile` records.
  - Distinguished upload `original_name` metadata from attached-file
    `visible_name` metadata.
- **Exceptions:**
  - Added `FieldValueError` for explicit field conversion failures.
  - Row add and update failures now report the failed batch number and IDs of
    rows completed by earlier non-atomic request chunks.
- **Row Writes:**
  - Unified singular create, batch create, singular update, batch mapping
    update, and explicit `Row.update(values)` around Field-owned validation and
    encoding.
  - Added consistent row-ID, batch-size, writable-field, and response-shape
    validation before or at the request boundary.
  - Batch writes validate and encode every row before the first request and do
    not automatically retry or roll back partially completed writes.
- **Row Reads:**
  - Row indexing decodes only the requested value through its Field; decoded and
    raw mappings remain independently inspectable.
  - Password reads preserve hosted `true` or `null` values. Added
    `PasswordField.is_set()` for explicit boolean interpretation and retained
    the hosted string, `true`, and `null` write forms.
- **Testing and Documentation:**
  - Added credential-free scalar field tests and recorded hosted compatibility
    probes for nullability, numeric precision, and timezone-offset writes.
  - Added offline structured-value tests and live select, linked-row, and file
    assignment coverage against hosted baserow.io.
  - Added read-only write-path coverage and hosted Formula, Count, Lookup, UUID,
    Autonumber, and filter compatibility tests.
  - Added offline singular/batch encoding parity and partial-failure tests, plus
    hosted row-write parity coverage against baserow.io.
  - Added offline row-model and public-export coverage, hosted password-state
    coverage, migration guidance, and updated architecture documentation.


#### 2026-09-01: 0.1.0b5

- **Breaking Changes:**
  - All package-defined exceptions now inherit from `BaserowAPIError` through consistent row, filter, field, and row-value groups.
  - Low-level request timeouts, connection failures, other request failures, HTTP errors, and malformed JSON responses now raise package exceptions instead of raw `requests` exceptions or generic `Exception` instances.
- **Exception Handling:**
  - Removed duplicate row exception definitions and made every row operation exception inherit from `RowError`.
  - Added structured request, timeout, connection, and response exceptions.
  - `BaserowHTTPError` is now raised for every non-2xx response and exposes Baserow error details when supplied.
  - High-level row operations retain their existing operation-specific exceptions and preserve the underlying failure through exception chaining.
  - Validation failures are no longer indiscriminately converted into row update failures.
- **Request Handling:**
  - Prevented file-upload header changes from mutating the client's default headers.
- **Packaging:**
  - Added a PEP 517 build declaration while retaining the existing setuptools metadata.
  - Replaced direct `setup.py` build invocation with `python -m build`.
  - Added Twine to the development dependencies for distribution validation and publishing.
  - Separated test-only `python-dotenv` from runtime dependencies.
  - Excluded the test package from the installed wheel while retaining tests in the source distribution.
  - Replaced the deprecated license classifier with the equivalent SPDX expression.
- **Documentation and Testing:**
  - Corrected the documented error-handling contract, including Table method docstrings, and added offline exception and request-path coverage.


#### 2024-08-06: 0.1.0b4

- **Breaking Changes:**
  - **Renaming:**
    - `table.add_row()` renamed to `table.add_rows()` for consistency.
    - `row.content` renamed to `row.to_dict()` for a more Pythonic approach.
  - **Field Value Change:**
    - `lookup_field`: Value is now a list of values from linked rows in the linked table.
  - **Iterator Changes:**
    - Replaced `RowIterator` class with a standard Python generator.
    - `table.get_rows()` no longer supports the `return_single` option.


- **Changes:**
  - **Field Handling:**
    - Moved all `format_for_api` functions to field classes for consistency.
  - **Field Validation:**
    - Fixed validation in `base_text_field`.
    - Improved validation for `password_field`, `base_date_field`, and `row.update()`.
    - `base_date_field`: Validation and `format_for_api` now allow Python datetime ISO format.
    - `base_date_field`: Setting date field values allows slashes, single-digit months and days, and two-digit years.
    - `base_date_field`: Setting date & time fields allows bare dates, assuming `T00:00:00Z`.
    - Added `validate_value` support for `None` values in `BaseTextClass`.
  - **Field Formatting:**
    - Added `format_for_api` to `single_select_field` and `multiple_select_field`.
    - `file_field`: File uploads now use a dedicated requests session to avoid `Content-Type` issues.
  - **Field Enhancements:**
    - `file_field`: Use `visible_name` when downloading fields.
  - **New Properties:**
    - `table`: Added `writable_fields` property.
    - `row`: Added `row.fields` property.
    - `table.get_rows()`: Added `limit` and `iterator` parameters. Returns a list of rows by default.
  - **Validation Improvements:**
    - Improved validation for data passed in `row.update()`.
    - `table.update_rows()`: Uses `writable_fields` for validation.
    - `table.get_row()`: Improved input validation.
  - **Documentation:**
    - Updated documentation for the recent changes.
  - **Testing:**
    - Added a basic set of functional tests.


#### 2024--8-06: 0.1.0b3
- **New Features:**
  - **Generic Field Type:** Added a generic field type to serve as a default if a specific field type is not available.
  - **Password Field Type:** Added a password field type.
  - **Long Text Enhancements:** Introduced `long_text_enable_rich_text` property for long_text field type.
  - **Link Row Enhancements:** Added `get_options` method for link_row field type, which returns a list of values from the primary field of the related table.
  - **Link Row Field Properties:** Added `link_row_related_field_name` property to provide the field name for `link_row_related_field_id` in the related table.
  - **Link Row Limit Selection View:** Added `link_row_limit_selection_view_id` property to link_row fields.
  - **Count Field Enhancements:** Added `table_id` property to count field type.
  - **Documentation Updates:** Updated documentation for linked fields.

- **Enhancements:**
  - **Validation Improvements:** Added basic validation for link_row fields, ensuring the value is a list of strings or integers.
  - **Client Integration:** Added the baserow client to all Field class objects, enabling them to perform database operations. This was implemented primarily for the `TableLinkField`'s `get_options` function, which retrieves a list of valid options from the primary field of the linked table.
  - **Filter Corrections:** Corrected the compatible filters list for the lookup field type.
  - **Field Updates:** Corrected compatible filters for number field.

- **Removals:**
  - **Deprecated Functions:** Removed `link_row_related_field` and `link_row_related_table` as the API sets these to the same values as `link_row_related_field_id` and `link_row_related_table_id`.
  - **Redundant Methods:** Removed `get_options` and `get_related_table` functions from the `TableLinkRowValue` class, as these are more appropriate for the field class.

#### 2024-08-03: 0.1.0b2
- **Enhancements:**
  - **Improved Filter Handling:** The `_build_request_url` method of the `Table` class now uses a JSON serialized filter tree for more efficient and accurate filtering.
  - **RowIterator Enhancements:** Added `reset` and `reset_index` methods to `RowIterator` objects. `reset` will refetch data from the API, while `reset_index` only resets the internal index without refetching.
  - **Batch Size Parameter:** Added `batch_size` parameter to `Table` methods `add_row`, `update_rows`, and `delete_rows` to avoid excessively large API calls. The default `batch_size` is set to 10 rows.
  - **Paging Fixes:** Improved `RowIterator` and `make_api_request` functions to handle paging correctly.

- **Bug Fixes:**
  - **Parameter Correction:** Fixed incorrect "page_size" parameter in `Table.get_rows` method, changing it to "size".
  - **Test Updates:** Removed tests for the obsolete `FieldValidator` class.
